# Developer UI

The client uses [Dear ImGui](https://github.com/ocornut/imgui) (v1.91.9, fetched by `cmake/Dependencies.cmake`) for a minimal developer UI. With it you can log in, pick a server and a character, and see basic in-game information. The Lua windows below replace it for play.

## Pieces

- `src/ui/imgui_layer.{h,cpp}`: owns the ImGui context and the SDL3 and Vulkan backends. The Vulkan backend uses our volk loader and dynamic rendering, and records into the frame's command buffer inside the rendering that `VkContext::begin_frame` started (colour + depth). Fonts and sizes follow the display's content scale. The layer looks for Liberation Sans or another common system font and falls back to ImGui's built-in font.
- `src/ui/dev_screens.{h,cpp}`: the screens. Each one takes a view model and returns the player's action, and none of them does networking:
  - `login_screen`
  - `server_select_screen`
  - `character_select_screen`
  - `loading_screen`
  - `in_game_overlay`, made of the info panel, chat and spawn list
- `src/ui/spell_windows.{h,cpp}`: the spell gem bar, cast bar, spell book, buff and song windows and the target's buffs, with spell icons from the game's `spells0N.tga` sheets (A_SpellIcons: 40 × 40 cells, 6 per row, 36 per sheet). `src/app/spell_ui.{h,cpp}` builds their view models from `net::GameConnection` each frame and passes clicks back.
- `src/game/eq_names.{h,cpp}`: race and class names for display. Multiclass characters are shown as `SHD/CLR/WIZ`.
- `src/core/config.{h,cpp}` and `src/platform/paths.{h,cpp}`: the `key=value` settings file, `hailstone.ini` in the Hailstone folder beside the binary (or in `~/.config/hailstone`, `%APPDATA%\hailstone` or `~/Library/Application Support/hailstone` when that folder is not writable; `docs/layout.md`). It names the last server used (`login.profile`).
- `src/core/server_profile.{h,cpp}`: the saved servers the login screen picks from, one folder `servers/<id>/` each with a `server.ini` (name, address, port, username). New, Save and Delete edit them; Login saves the picked one. The username is kept when "Remember username" is ticked; the password never is. The Assets row shows the server's own files folder (`servers/<id>/assets`) with an Open folder button: files there replace the asset folder's of the same name for that server (`GameDir::set_overlay`, applied at Login). The old `login.host`, `login.port` and `login.username` keys become the first saved server. Test logins (`--user` with `--host`/`--port`) use a transient server that is never saved (`--password` is on the command line, which every user of the computer can read in the process list: a test account's only); `--server <id or name>` picks a saved one.
- `src/app/ui_demo.{h,cpp}`: the demo below.

## Demo

```sh
build/hailstone/hailstone --ui-demo login           # start on the login screen
build/hailstone/hailstone --ui-demo game --zone qeynos2 # in-game overlay over the zone viewer
build/hailstone/hailstone --ui-demo chars --frames 20 --screenshot chars.png   # to screenshots/chars.png
build/hailstone/hailstone --ui-demo login --ui-scale 1.5 # override the display scale
```

The screens are `login`, `servers`, `chars`, `nochars`, `loading`, `game` and `items` (a fake inventory and corpse). In the demo:

- F1 to F7 switch between the screens.
- The buttons walk through a fake flow: any username and password log in, then server, character, loading and in game.
- Chat lines you type are echoed back.

While the UI has keyboard or mouse focus, the camera ignores that input. Holding the right mouse button still turns the camera.

The UI has the keyboard only while an edit box is being typed in, a modal dialog is open, or a window asks for it (`ui.CaptureKeyboard`). A click or drag on a button, slider, title bar or window background does not take it (`ui::keyboard_for_ui`), so movement keys held through the click stay held, as in the original.

## Using it from an app loop

```cpp
ui::ImGuiLayer ui(window, vk);           // after VkContext
while (window.poll_events()) {
    ui.new_frame();
    if (auto a = ui::login_screen(login_view); a == ui::LoginAction::Submit) { /* start login */ }
    auto f = vk.begin_frame(clear);
    if (!f) { ui.end_frame_without_render(); continue; }
    /* draw the world */
    ui.render(*f);                       // last, before end_frame
    vk.end_frame(*f);
}
```

### Extended chat channels

The chat windows' channels 57..107 and user colours 355..408 (docs/mechanics.md "Extended chat routing") are
Hailstone's, used only when a server sends those colours. `eq.ChatFilterGroups()` gives the Filters menu's submenus
as `{id, parent, name}` (parent 0 is the Filters menu): Chat Channel, Melee and Spells, then Extended (server) and
its submenus. `eq.ChatFilters(slot)` keeps `id`, `group`, `name` and `on` and adds `menu` and `parent` (the item's
menu and the menu that holds it); `eq.ChatSetFilter` still takes a channel or a menu's name, a menu's ALL moving its
own items only. The modern pack draws the menus from these; the gamepad pack has no filter menu. The channels are
kept as `ChannelMap0..107` in the character's UI ini and the colours as `User_1..153` in its `chat.ini`; a file
written before them (ChannelMap0..56, User_1..99) loads as it was, the new ones on the main window and at their
defaults.

## The Lua windows

`eq.UiAnimation(name)` explicitly resolves the first frame of a named `Ui2DAnimation` from the installed/default XML and returns `texture, u0, v0, u1, v1, width, height`, or nil for unavailable/invalid art. Width and height are the authored frame dimensions, not the atlas size. This read-only opt-in works in an icon-only pack without changing `eq.UiTexture`, `eq.ChildArt` or the pack's normal art policy. Only a relative atlas filename and an entirely contained positive crop are accepted. Resolve handles each draw rather than retaining them across texture-cache eviction. No game art or XML is bundled with the client.

The windows are Lua scripts drawn with ImGui, grouped into user interfaces: every folder of `ui/` with a `ui.ini` is one (`src/ui/ui_packs.h`), copied next to the executable at build time and reloaded when its scripts change (the build copies only the scripts whose contents changed and deletes those gone from the source, `cmake/SyncUiPacks.cmake`, so a rebuild reloads only what it changed). Each saved server keeps its own (`servers/<id>/server.ini` `[Server] ui`, picked on the login screen's Interface list, which every pack's login screen shows on its main card, or in Options > Display > Interface > User Interface; the login screen switches to it at once, and a saved server keeps it at once); `hailstone.ini` `ui.name` is the one for a new server or a test login (`modern` when it is missing), and each keeps its scripts' settings in `ui/settings/<name>.txt` of the Hailstone folder (not inside the pack, which an update replaces).

- `ui.ini`: `name` and `description` (shown in the Options window), `input` (what it is built for: `mouse`, `gamepad`, `touch`), `game_art` (`icons`: of the game's `uifiles/default` only the item, spell and gem icon sheets load, `UiTextures::set_all_art`; `all`: every file). Scripts `dofile` paths relative to their UI's folder (`"lib/sidl.lua"`).

    `catalog_token` and `state_revision` are opaque unsigned 64-bit decimal strings: pass them back unchanged, without `tonumber`.
